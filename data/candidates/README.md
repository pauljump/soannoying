# Screened candidates

These are the result of a first Big Annoyance Test pass over the v0.1 raw observations.

They are **screened candidates**, not reviewed problem records. The source links show why each pattern is worth a closer look. The wording is a working description, not a claim that the problem is common or solved.

The first pass used a cheap text screen over all 1,340 observations, followed by a judgment-heavy review of the strongest 100 distinct leads. A second bounded Haiku mining run added 89 source observations; four more candidates survived the same filter. The pass kept patterns that looked repeated, costly, hard to work around, and broader than one isolated product complaint. It did not use the provisional `fixability` label as evidence.

The next step is community review: merge overlapping candidates, reject weak ones, add better evidence, and only then create records in `data/problems/`.
